# 🚀 Valoqui: Zero to Hero (Onboarding Guide)

Welcome to Valoqui! This guide is designed to take you from a complete beginner to a confident contributor in this codebase. Grab a coffee, and let's dive in.

## 1. What is Valoqui?

Valoqui (internally codenamed *Lingua*) is a real-time AI conversation partner for language learning, currently targeting Spanish.

**The core problem it solves:** Voice AI is often slow and robotic. Valoqui solves this by combining ultra-fast cloud LLMs (Groq) with on-device VAD and TTS to achieve human-like conversational latency.

## 3. The Mental Model (How the App Thinks)

Valoqui is built on a few core philosophies:

1. **Feature-First Clean Architecture:** The app is divided by features (`auth`, `home`, `speaking`, `report`). Inside each feature, there are 3 strict layers: Domain, Data, and Presentation.
2. **Immutability & Unidirectional Flow:** State is managed by **BLoC**. All states are immutable classes generated by **Freezed**, while events typically use **Equatable** for simplicity. You cannot mutate state; you can only yield new states.

   ```dart
   // Example: An immutable event in lib/features/speaking/bloc/speaking_event.dart
   class SessionStarted extends SpeakingEvent {
     final String userCefrLevel;
     final String userId;
     const SessionStarted({required this.userCefrLevel, required this.userId});
     
     @override
     List<Object?> get props => [userCefrLevel, userId];
   }
   ```

3. **No Hidden Failures:** We use **fpdart** (`Either<AppFailure, Success>`). A function never throws an exception into the void. It always explicitly returns a `Left(Failure)` or a `Right(Success)`.
4. **Bring Your Own Key (BYOK):** Valoqui is free because users provide their own Groq/Gemini API keys. We securely store these in the Android Keystore/iOS Keychain.

## 5. The Golden Path (The Voice Pipeline)

The heart of Valoqui is the `SpeakingBloc` (`lib/features/speaking/bloc/speaking_bloc.dart`). This is how a conversation flows:

1. **Listen:** The user speaks. `SherpaVadDatasource` monitors the mic. When silence is detected, it emits the audio buffer.
2. **Transcribe:** `SherpaSttDatasource` takes the audio buffer and decodes it on-device using the Moonshine model. It returns a transcribed string.
3. **Think:** `LlmRepository` sends the transcript to Groq LLaMA 3.3. **Crucially**, it streams the response back token by token.
4. **Speak (Early Trigger):** `SpeakingBloc` buffers the tokens. As soon as it sees a sentence boundary (`.`, `?`, `!`), it sends that sentence to `SherpaTtsDatasource` (VITS/Piper) to speak immediately, while the LLM is still generating the rest!
